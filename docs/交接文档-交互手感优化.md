## 三、手感问题诊断（带代码位置）

### 1. 抽牌入口远：牌堆不可点
必须点右下角「结束回合」按钮（`#btnEnd`）才能抽牌。牌堆（`.pile-stack`，
`styles/main.css:475`）只有视觉展示，没有任何点击行为。
唯一例外：炸弹放回模式下 `main.js` 的 `enableBombPlacement()`（main.js:279-307）
会给牌堆临时挂 click（按点击高度决定炸弹插回位置）。

### 2. 手牌是平铺的，不像「握在手里的牌」
`.hand`（main.css:778-787）是 `flex + gap + flex-wrap`，牌多时折成两行。
没有任何旋转/弧线/层叠。

### 3. 牌的来去完全没有动画（最关键的发现）
`View.renderHand`（view.js:257-295）每次调用都 `wrap.innerHTML = ''` 然后
**整体重建全部手牌 DOM**。后果：

- 出牌的牌瞬间消失、摸牌瞬间凭空出现，无任何过渡。
- CSS 里现成的 `.card.entering`（cardIn 动画，main.css:912-916）和
  `.card.leaving`（cardOut 动画，main.css:948-951）**是死代码**——JS 从未给任何
  元素挂过这两个类。这是前人想做但没做完的部分。

### 4. 抽牌缺「从牌堆飞出来」的物理过程
现在的抽牌反馈（main.js `playEvents` 的 `draw` 分支，main.js:92-108）是：
牌堆轻顿（`View.bumpDeck`）→ 台面中央揭晓（`View.showDrawnCard(card, 1250)`）→
`await delay(760)` → 手牌里 `newly-drawn` 高亮。三重反馈都有，但没有一张牌
从牌堆位置移动到手里的连续动画；对手抽牌也只有头像抖动（`showOpponentDraw`）。

### 其他已确认可利用的现状
- 所有动画/transition 都会被 main.css:1394-1400 的 `prefers-reduced-motion`
  规则自动关闭——新增动效只要用 animation/transition 就天然尊重无障碍设置。
- `App.busy`（动画锁）是现成的输入锁机制，新交互要遵守它。
- 抽牌后的 `delay(760)` 是玩家的「看清牌面」时间，压缩它要谨慎（browser.test.js
  有对 drawFlash 的时序断言，改了之后可能需要微调测试等待，不是删断言）。

## 四、待办：优化实施方案（已设计好，未写代码）

> 原则：**引擎层（src/core）零改动**，只动 view.js / main.js / main.css。
> index.html 结构不动（所有测试 selector 不变）。

### A. 点击牌堆直接抽牌
- `main.js bindUI()`：给 `.pile-stack` 挂**常驻** click 监听。满足条件
  （`G.current === App.humanId`、`phase === 'playing'`、`!G.pendingBomb`、
  `!App.busy`、非 `awaitingTarget`）时调 `humanEndTurn()`；不满足时静默返回。
- `render()` 里随状态给牌堆加/去 `.can-draw` 类：金色呼吸光晕 + `cursor:pointer`
  + hover 抬升 + title「点击抽牌」。
- **冲突注意**：炸弹放回模式（`enableBombPlacement`）有自己的临时监听器，常驻
  监听器里检测到 `G.pendingBomb` 必须 return，两套逻辑不能打架。
- 顶栏/提示条文案同步改：「出牌后点击牌堆（或按空格）抽牌」。
- `#btnEnd` 按钮和空格键保留，作为兜底入口。

### B. 手牌扇形展开（本方案工作量最大的一项）
- **先改 renderHand 为按 uid 复用 DOM**（这是后面 C/D 的前提）：
  模块级 `Map<uid, element>`；已有 uid 复用元素只更新 class，新 uid 创建元素，
  消失的 uid 移除。`newly-drawn`/`selected`/`playable`/`locked` 等状态类照旧按
  render 参数打上去（测试依赖这些类名，不能改名）。
- 每张牌由 JS 算 `--rot`（旋转角）、`--lift`（弧线抬升）、`--z`（层叠序），
  CSS 合成：`transform: rotate(var(--rot)) translateY(var(--lift))`，
  `transform-origin: 50% 130%` 模拟手持圆弧。
- 重叠自适应：按容器宽度与手牌数算步距（`--step`），牌少几乎不重叠、牌多自动
  收紧；**去掉 flex-wrap**（扇形天然解决折行）。
- hover/selected：在保留自身旋转角的基础上额外上抬 + 放大 + z-index 置顶；
  `.locked`、`.aiming` 行为不变。
- `cardIn` 进场动画只定义 `from`（落点即扇形位置）——B 完成后它自动不再是死代码。
- 窄屏 ≤620px 减小旋转角与抬升系数。

### C. 抽牌飞行动效
- 新增 `View.flyCard(fromRect, toRect, opts)`：fixed 定位飞行牌（卡背或卡面），
  transition 约 240-260ms 后移除。
- 真人抽牌：牌背从牌堆飞到台面中央 → 现有 `drawFlash` 揭晓（`#drawFlashCard`
  结构不动）→ 手牌高亮。揭晓后的 `delay(760)` 可微调到 ~600ms。
- AI 抽牌：牌背从牌堆飞向该对手头像（`.opponent[data-pid]`），落地接现有抖动。

### D. 出牌飞向弃牌堆
- `playEvents` 的 `play` 事件：真人出牌时取该牌元素坐标（注意 render 在事件播完
  才执行，此时旧 DOM 还在），克隆一张卡面飞向弃牌堆（`.discard-top`），约 380ms
  带轻微旋转，原牌隐藏；AI 出牌从头像位置起飞。
- 弃牌堆顶更新仍由 `renderStage` 完成，飞行克隆只做视觉衔接。

### E. 细节反馈
- 卡牌 `:active` 按压反馈（scale .96）。
- `turn` 事件切到真人时，牌堆与结束回合按钮各脉冲一次（提示「该你了」）。
- 顺手清理 `.entering/.leaving` 死代码（B 会真正用上进场动画）。

### F. 明确不改的东西
- 引擎/AI/卡牌数据/index.html 结构、音效、爆炸特效、日志、弹层。
- README 中记录的测试断言一个都不许动语义。

## 六、风险与备忘

1. **手牌 DOM 复用改造（B）是唯一有回归风险的点**：browser.test.js 靠
   `#hand .card` 数量与类名断言，复用逻辑必须在每次 render 后保证 DOM 与状态
   完全一致（包括 target 选完后对手高亮消失）。
2. 扇形 transform 会改变 hit-test 区域，`#hand` 的 click 委托（main.js:525）依赖
   `ev.target.closest('.card')`，重叠后点到的是 z-index 最上面的牌，符合直觉，
   但要实测确认没有「点 A 出了 B」的错位。
3. 单文件版由 `tools/build-standalone.js` 重新生成，改完源码后**必须重建并跑
   check-standalone**，否则单文件版还是旧交互。
4. 本项目 README 是「设计决策档案」性质，实施完成后建议把本次改动的结论
   （比如「手牌为何从平铺改扇形」「renderHand 为何从重建改复用」）补进 README
   相应小节，沿用其注释风格。
