# 炸弹猫 · 单机版

一个纯前端的卡牌小游戏。双击就能玩，无依赖、无构建、无需联网。

---

## 快速开始

**方式一：常规版（推荐）**

```
直接双击 index.html
```

素材放在同级 `assets/` 目录里，所以 **`index.html` 和 `assets/` 必须在一起**。

**方式二：单文件版（任何预览器都能开）**

```
双击 炸弹猫-单文件版.html
```

3.5 MB 单文件，素材全部内联成 data URI。
适合放进各种 HTML 预览器/侧边栏——那些环境通常只渲染单个文件，
取不到同级目录，常规版会显示一片裂图。

想重新生成（素材更新后）：

```bash
node tools/build-standalone.js      # 产物：炸弹猫-单文件版.html
node tests/check-standalone.js      # 在空目录里验收，确认无裂图
```

**方式三：本地服务器**

```bash
npx serve .
# 或
python -m http.server 8080
```

**方式四：联机对战（和朋友）**

```bash
node server/server.js        # 默认 8080 端口，页面和 WebSocket 同源
```

开局面板选「联机 · 和朋友」→ 一人点「创建房间」拿到 4 位房间码 →
朋友在同一页面输入房间码「加入」→ 房主点「开始对局」。
服务器是零依赖的 Node 脚本（手写 WebSocket，不需要 `npm install`），
规则跑的是和单机同一份引擎。断线的玩家 90 秒内重开页面会自动回到座位。

### 素材没加载？

页面会自己弹一条红色提示，直接告诉你浏览器**实际去请求的绝对路径**。
常见原因：把 `index.html` 单独拷走了、在只渲染单文件的预览器里打开、
或者直接打开的是别的文件夹里的旧副本。改用单文件版即可绕过。

## 玩法

轮流出牌，每回合结束时要**从牌堆抽一张**。抽到**炸弹猫**时：

- 手上有「拆除」→ 拆掉它，然后把炸弹秘密放回牌堆任意位置，继续游戏
- 没有「拆除」→ **立刻出局**

活到最后的人获胜。牌堆抽空时，弃牌堆会重新洗回牌堆。

### 卡牌一览

| 卡 | 数量 | 效果 |
|---|---|---|
| 炸弹猫 💣 | 人数−1 | 抽到就炸，除非用拆除 |
| 拆除 ✂️ | 6 | 拆掉炸弹，并把它放回牌堆任意位置 |
| 预测未来 🔮 | 5 | 偷看牌堆顶 3 张 |
| 攻击 ⚔️ | 4 | 自己不抽牌，下家要连抽 2 张 |
| 跳过 ⏭️ | 4 | 这回合不抽牌 |
| 洗牌 🌀 | 5 | 打乱牌堆，已知顶牌信息作废 |
| 求饶 🙏 | 4 | 指定对手，他必须交给你一张牌 |
| 帮忙 🤝 | 4 | 指定对手，他会主动给你一张牌 |
| 否决 🚫 | 4 | 取消上一张打出的牌 |
| 摸两张 🎴 | 1 | 抽 2 张，可再弃掉 0~2 张 |
| 无效果 🃏 | 5 | 什么也不发生 |

### 两条容易忽略的规则

1. **开局手上没有炸弹。** 炸弹是在发完手牌之后才洗进牌堆的，所以不存在「手里攥着一张炸弹猫怎么处理」的问题。
2. **不能把对手掏空。** 求饶/帮忙无法要走对方最后一张牌，否则空手玩家抽到炸弹必死，游戏会失去博弈感。

### 分层约定

- **引擎层（`src/core`）不引用任何 DOM**，可以在 Node 里直接 `require` 跑几万局。
- **视图层只读引擎快照**（`Engine.getState`），从不直接改游戏状态。
- **所有对局随机都来自注入的 `rng`**，给定种子即可完整复现一局。

这套约定让「规则是否正确」可以脱离浏览器被自动化验证。

### 测试里固化了哪些「不能退回去」的结论

- 开局任何人手上都不能有炸弹
- 开局牌堆顶不能是炸弹，且炸弹在牌堆中的位置必须均匀分布（见下方「曾出过的严重 bug」）
- 炸弹猫不能主动打出，也不出现在可出牌列表里
- **抽到普通牌绝不能消耗「拆除」、也不能触发放回炸弹的流程**
- 求饶/帮忙不能把对手的手牌掏空
- 卡面必须渲染出名字与说明（防止命名空间挂错一层导致卡面全空白）
- **抽牌必须留下可追溯的反馈**：记住抽到哪张、台面展示牌面、手牌里高亮那一张
- **桌上不能再出现固定的炸弹明牌**（避免被误解成场上有炸弹）
- 难度梯度：hard > normal > easy，且 hard 的躲避行为显著多于 easy
- hard 把拆掉的炸弹放回牌堆深处，而不是塞在牌堆顶

### 曾出过的严重 bug（留档，避免复发）

**抽牌逻辑丢了一行提前返回。** `resolveDraw` 里的
`if (card.type !== 'bomb') return ...` 被误删，导致**抽到任何牌都会走一遍「拆除」流程**：

- 玩家每抽一次牌就白丢一张「拆除」，抽到的那张牌还被当成炸弹放回牌堆
- 等到真炸弹出现时手上早已没有拆除 → 必死
- 表现就是玩家反馈的「每局开局必抽到炸弹」，其实是「每局都裸奔」

这个 bug 能存活很久，是因为当时的测试只验证了「抽到炸弹会不会正确处理」，
**没有一条断言检查「抽到普通牌不该发生什么」**。修复后平均对局长度从 6.4 回合
恢复到 31.9 回合——这个数字本身就是最好的体检指标。

**「开局顶牌不是炸弹」的修正也写错过。** 早期实现是「与第一张非炸弹交换」，
而第一张非炸弹几乎总是 index 1，于是所有本该落在顶部的炸弹（12.5%）全被堆到第 2 张，
使 index 1 的炸弹概率翻倍到 24%——第二个行动的人几乎必中。现在改成放回一个
均匀随机的「第 2 张之后」的位置。

## 难度设计

本作真正的核心权衡，和直觉相反：

> **手上有「拆除」时，抽牌几乎是纯赚。**
> 因为多一张牌就多一次摸到下一张拆除的机会，而拆除才是真正的命。
> 只有手上**没有拆除**时，抽牌才等于俄罗斯轮盘，这时「跳过 / 攻击」才值钱。

在正确的规则下（每局约 30 回合）实测各策略对 2 个简单 AI 的胜率：

| 策略 | 胜率 |
|---|---|
| 抢牌（求饶/帮忙）+ 有拆除就抽 + 没拆除才躲 | 46.0% |
| 同上但不抢牌 | 38.9% |
| 一味躲避（早期错误模型） | 34.9% |
| 关掉抢牌 | 27.3% |

所以三档的差异集中在**抢牌积极性**上（最有效的单一杠杆），其次是避险判断：

- **轻松**：不会为了避险去用跳过/攻击（新手那种「攥着保命牌硬抽」），也很少抢牌
- **普通**：偶尔看牌、偶尔躲避，但经常判断失误，大致势均力敌
- **困难**：积极抢牌；只在「手上没拆除」时才躲；会把拆掉的炸弹塞进牌堆最深处

调参入口在 `src/ai/ai.js` 的 `PROFILES`（已导出，可直接改）。

实测梯度（三档同场、轮换座位、750 局）：

```
hard 40.0%  |  normal 32.5%  |  easy 27.5%     （公平份额 33.3%）
```

### 关于「炸弹放回哪里」

直觉是把炸弹放牌堆顶立刻坑下家，但实测相反：

- 放顶部 → 下家多半还有拆除，能活，并且会把炸弹继续往下传，绕一圈容易回到自己手上（26.9% 胜率）
- 放底部 → 自己这轮彻底安全，炸弹要等牌堆快抽空才出现，中间由所有人分摊风险（32.0% 胜率）

所以困难 AI 一律往牌堆深处塞。

## 一些实现细节

### 抽牌反馈

抽牌是这个游戏最紧张的一刻，所以做了三重反馈：

1. **牌堆轻顿一下**，表示被抽走一张
2. **台面中央摊开这张牌**（放大版），顶部标「你抽到了」，停留约 1.2 秒
3. **手牌里那一张高亮**：金色描边 + 左上角「新」角标，一直保留到你下次抽牌

对手抽牌只给一个「拿走一张」的轻微晃动，不暴露牌面——和实体桌游玩起来看到的信息量一致。

> 踩过的坑：如果淡出写在 keyframe 里，「多停留一会儿」就按不住；进场用动画、停留/淡出用 transition 才对。

### 关于桌上那张「炸弹」

早期版本在牌桌左侧固定放了一张炸弹明牌，本意是告诉玩家「本局有几张炸弹」，
但玩家会把它理解成**场上真的躺着一张炸弹**，而且它永远不动，很迷惑。
现在改成顶栏的一个数字（炸弹图标 + 数量），鼠标悬停才显示说明。桌面只留牌堆和弃牌堆。

### 美术素材怎么接进来的

**卡牌**由三层叠成：`frame.webp`（白底金边卡框，铺满整张牌）+ `icon/face` 插画（手绘猫）
+ 深墨色卡名。小卡（手牌）用 `icon/`，大卡（抽牌浮层）用 `face/` 并展开完整说明文字。

**爆炸**用 `fx/boom-sheet.webp`：6 列 × 2 行、每帧 512×512、共 12 帧，
用一个 `div` 按 `background-position` 逐帧推进（`background-size: 600% 200%`），
配合 canvas 粒子碎屑叠出层次。

**图标**没有用 `<img>` 也没用 CSS mask，而是编译成**内联 SVG sprite**：

> `<img>` 不继承 `currentColor`，深色按钮上会变成看不见的黑图标；
> CSS mask 对没有内在尺寸的 SVG 支持不稳，实测完全不显示。
> 内联 `<symbol>` + `<use>` 后，图标直接跟随按钮文字色，最可靠。
> 图标源文件仍在 `assets/ui/*.svg`，改完跑 `node tools/build-icons.js` 重新生成。

素材路径写错不会报错、只会静默变成裂图，所以集成测试里专门有一道
「引用的 46 个素材全部存在」的检查。

### 其他

- **联机的核心是「权威服务器 + 引擎复用」**：完整状态只在服务端（手牌是隐藏信息，
  P2P 互传状态等于摊牌），服务端直接 `require` 同一份 `engine.js` 结算所有动作——
  单机联机跑的是同一套规则。每个玩家收到的是**按座位裁剪的私有快照**
  （自己的手牌 + 自己的合法动作），事件流也按座位脱敏：
  对手抽到的牌、炸弹插回的位置、预测未来的牌面，都只发给本人。
  WebSocket 是手写的 RFC6455 子集（`server/ws.js`，约 200 行），
  延续整个项目「零依赖」的取向。断线 90 秒内凭 seat token 重连并补发快照。
- **音效全部是 WebAudio 现场合成**，没有使用音频文件。爆炸是低频噪声 + 降调正弦的叠加。
- **粒子用 canvas 绘制**，爆炸时在对应玩家卡片位置爆开，带重力与衰减。
- **响应式**：860px / 620px 两个断点，窄屏会隐藏日志面板。
- **无障碍**：尊重 `prefers-reduced-motion`，系统开启「减少动态效果」时会关闭动画。

## 已知取舍

- ~~没有联机~~ **联机已实装**（零依赖 Node 服务器 + 手写 WebSocket），但按 v1 取舍：
  - 求饶/帮忙由引擎代为选牌（与单机一致），没有做「被点名的人自己挑一张」的交互；
  - 玩家掉线超过 90 秒，房间直接解散（没有 AI 接管、没有暂停）；
  - 重连只补发当前快照，不重放错过的动画事件；
  - 没有再战流程，结算后回开局面板重新开房。
- 「否决」目前是简化实现（取消上一张打出的牌），没有做完整的「连锁否决」窗口。
- 「摸两张」的弃牌阶段没有实现交互，抽到就留在手里。
- 素材包里的 `fx/` 手动只用了爆炸精灵图；冲击波、烟雾、火花、碎屑、拆弹光晕、
  屏幕光晕尚未接入（已随素材拷入，后续可补）。
- `brand/icon-512` 与 `brand/logo-*` 目前用于 favicon 与顶栏，没有做 PWA manifest。
